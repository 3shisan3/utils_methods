# Axure RP 查看器功能评估

## 结论

原工具具备 RP9 容器读取、页面名称匹配、静态页面生成、缩略图、网页上传及 Windows 文件选择的主要流程，适合轻量静态预览，尚不是完整 Axure 播放器。原目录只有四个 Python 文件与说明，说明提到的 sample.rp、target.rp 未提供。本次使用合成 RP9 容器验证流程，真实文件视觉效果、版本兼容性与大文件性能仍待验证。

## 本次引入与修复

采用当前仓库“独立工具目录 + 中文 readme.txt”的结构，保留格式解析、渲染、服务和系统入口的职责划分。

- 原 multipart 解析使用 strip 删除文件末尾换行，可能损坏二进制；改用标准库 MIME 解析。
- 原同名上传共用源文件与结果目录，存在并发覆盖和失败污染；改用独立任务目录，只发布成功结果，并清理上传原件。
- 增加 64 MiB 请求体限制、上传读取超时、扩展名及空文件校验、浏览器 Origin 检查；静态路径使用真实路径检查，禁止访问内部任务目录。
- 页面列表、警告和页面名称插入 HTML 前转义；限制提取图片扩展名。
- 未知标签原先直接猜测两个整数且不报警，现在明确抛出 ParseError。未覆盖格式可能更早失败，避免静默生成错误结果。
- 增加 RP9 签名检查；未找到页面改用解析异常，避免库调用触发进程退出。
- 修复 Windows 文件对话框缓冲区指针赋值；非 Windows 浏览器路径使用标准 file URI；退出服务时关闭套接字。

## 后续优化建议

| 优先级 | 问题与建议 |
| --- | --- |
| 高 | 顶层控件才计算位置、大小、填充和图片，嵌套控件仅递归生成文本；应统一递归布局，补全组合、表格、动态面板默认状态、裁剪、边框和旋转。解析交互引用不代表执行交互。 |
| 高 | 索引解码遇到损坏会返回部分内容，条目遍历可能静默停止；应严格检查长度、距离和结束标记。gzip 仍整体解压，需增加解压预算和任务并发限制；上传大小限制不能限制解压后的内存。 |
| 中 | 目前页面树仅保留页面及缩进，无页面文件夹会被过滤；建议保留文件夹，增加折叠、搜索和当前页高亮。名称匹配回退应明确报告。 |
| 中 | 页面被多次解码，GUID 匹配存在双层循环；建议缓存解码结果、建立反向索引，增加任务进度、取消与结果清理。 |
| 后续 | RP8/RP10、母版、自适应视图、渐变和交互执行需要独立样例与实现，不能宣称现有代码已完整支持。 |
| 体验 | 异步完成后自动开窗可能被浏览器拦截，已有手动链接可用；原生窗口尚未区分取消和调用错误，目录记忆建议移至用户配置目录。 |

## 验证范围

回归覆盖上传尾字节完整性、同名任务隔离、失败清理、合成 RP9 到静态页面全流程、未知标签拒绝及图片扩展名限制。未做真实 RP 视觉对比，未实际打开浏览器或弹出 Windows 对话框。
